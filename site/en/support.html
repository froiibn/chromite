Features and database support

Chromite connects to any database that has a JDBC driver, runs queries and works with the results. The table below shows how far each of the other features goes on each database. It lists only what was checked against the code and design documents of Chromite 0.1.3.

Reading the table

  • Supported: the feature works on that database. Small print gives conditions.
  • Partial: only part of the feature works. The missing part and the reason are given.
  • Not supported: the feature is not available, for one of two reasons. “Not provided by the database” means the database has no such feature or API. “Not supported by Chromite yet” means Chromite has no implementation for that database, whether or not the database itself has the feature.
  • Needs checking: the menu is enabled through shared code, but it has not been checked on that database.

Columns

Query editor and results
The SQL editor, result grid and Object Explorer. They work on every database that connects through JDBC. Databases not in the table connect too once you add their JDBC driver in the Driver Manager.
Procedure debugger
Breakpoints, Step Over, Step Into, Step Out, variables and the call stack, and changing a variable's value while stopped.
Execution trace
Runs a SQL Server stored procedure once and records each statement's line, duration, CPU, rows, reads and writes (Extended Events). It is the alternative for SQL Server, which has no procedure debugger.
Actual plan
With the query window's toggle on, the statement runs once and its actual plan comes with it.
Estimated plan
Shows the plan without running the statement. Any driver that provides plans uses the same view.
Sessions and locks
The Activity Monitor's processes and locks: the blocking chain from the head blocker, the locks of each session, ending a session.
Job scheduler
View, create and change the jobs in the database's own job scheduler (SQL Server Agent, DBMS_SCHEDULER, pg_cron, events).
Space and logs
The Activity Monitor's disk usage and server logs (errors, warnings, slow queries).
Maintenance
Index rebuilds, statistics updates, VACUUM and similar tasks, run after a preview and a confirmation.
Replication status
The state of replication and availability setups, read-only.
Security editor
Edit logins, users, roles and permissions.
Native backup and restore
Back up and restore with the database's own tools (SQL Server BACKUP and RESTORE, pg_dump and pg_restore, mysqldump). pg_dump and mysqldump must be installed on this PC.
Schema compare
Compares the tables, columns, indexes and foreign keys of two databases from the Object Explorer and writes a change script, the same way on every database. Between different kinds of database, views, routines, triggers and sequences are compared by existence only. UNIQUE and CHECK constraints, comments and permissions are not compared.
Chromite Agent common tools
Schema, data and query tools, and a tool that runs diagnostic SQL written by the model, read-only. With any database it diagnoses by querying the system information directly. Statements that cannot be shown to be reads are not run.
Agent dedicated diagnostics
Tools that read plans, locks and the blocking chain, sessions, waits and space with ready-made diagnostic queries. Databases without them are diagnosed with the common tools.
Driver
Pre-installed: in the installer. Downloaded on first connect: fetched the first time you connect, when there is internet. Add it yourself: point the Driver Manager at the JAR file.
Offline bundle
Pack drivers into one file in the Driver Manager on a PC with internet and install it on a closed-network PC. Pre-installed drivers need no bundle.

Database-specific features

  • SQL Server: SQL Server Agent jobs, steps, schedules, alerts, operators, error log and Job Activity Monitor. Express has no Agent.
  • Altibase: tables coloured by storage type, server output, sessions and locks, the actual plan, and replication status and commands.
