Privacy

The app's update check

When the update check is on, Chromite reads this site's release list (https://chromite.seizia.com/downloads/releases.json) and, when there is a new version, downloads its installer from the same place.

  • The requests carry one fixed User-Agent, the same for every copy of Chromite, and nothing else: no installation ID, account, usage history, database details or cookies.
  • Without an internet connection, or when a company network blocks it, the check is skipped quietly.
  • You can turn the automatic update check off in Options.

Chromite Agent

Chromite Agent sends nothing until you set it up. To use it, choose a provider in the Chromite Agent tab of Options (Anthropic Claude, OpenAI or an OpenAI-compatible address, Ollama) and enter your own API key or Ollama address. Requests go from this computer straight to the address of the provider you chose. They do not pass through this site or any other Chromite server, and Chromite does not collect them.

  • What is sent: what you write in the chat and the whole conversation so far, the name and driver of the current connection and the database name, and the results of the tools Chromite Agent runs. Tool results can contain structure (tables, columns), query text and query results (100 rows at a time by default, at most 10,000), execution plans, and server status such as sessions, locks and server settings. Connection passwords and credentials are never put into tool results.
  • By default, read tools run without asking. Tools that change data or structure ask before they run, and on production connections they are blocked until you allow them for that connection.
  • With Ollama, requests go only to the Ollama server you entered (usually this computer or your company network).
  • What reaches a provider is covered by that provider's privacy policy and terms.
  • From the version after 0.1.0, API keys are stored encrypted in the secure storage of the operating system on this computer (on Windows it is tied to your Windows account, on macOS it uses the Keychain), never in a settings file, and are not shown again in the settings. Version 0.1.0 stored them unencrypted in a settings file of the Chromite workspace; the newer version moves such a key to the secure storage the first time it uses it and deletes the unencrypted copy. Conversations and the tool log stay in the workspace.

The local MCP server is off by default. When you turn it on, it accepts only requests from this computer (127.0.0.1) that carry the token shown in the settings. The same permission and confirmation rules apply to other AI tools connected to it; where such a tool sends the results is up to that tool's settings and terms.

Saved passwords

  • Saved connection passwords and other saved credentials (SSH and proxy passwords, network profiles, Maven repositories) stay on this computer, encrypted in the secure storage of the operating system (on Windows it is tied to your Windows account, on macOS it uses the Keychain). They are never sent anywhere and are not kept in the workspace files.
  • Earlier versions kept them in the workspace, in a file encrypted with a key that was the same for every installation, or in a settings file without encryption. The newer version moves them to the secure storage when it starts and deletes those files and settings after checking the moved copy.
  • Because of this, a workspace copied to another computer does not carry the passwords. To move connections with their passwords, use File > Export Connections with a passphrase you choose.

This site

  • No cookies, analytics, ads, or external fonts or scripts. Every file comes from this site only.
  • Like any web server, it logs requests (IP address, time, requested address, User-Agent, response code) and deletes the log after 30 days. The log is used only to run the server and deal with abuse.

Usage statistics

Chromite does not collect or send feature usage statistics.
