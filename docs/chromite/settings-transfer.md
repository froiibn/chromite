# 설정 내보내기·가져오기 (설정, 드라이버, 쿼리 라이브러리, 스크립트, 연결)

## 목적

새 PC로 옮기거나 여러 PC를 같은 설정으로 맞출 때, 옵션·드라이버 설정·쿼리 라이브러리·스크립트를 손으로 다시 만들지 않게 한다
(감사 [A-C14](swt-parity/A-platform.md), SWT `tools/configuration`·`tools/project`·`tools/scripts` 마법사). 연결은 #108의
암호화한 연결 파일([connection-transfer.md](connection-transfer.md))을 그대로 쓴다.

가져오기는 바꾸기 전에 무엇이 바뀌는지 보이고(미리 보기), 충돌마다 건너뛰기·바꾸기·둘 다 두기를 고르게 하며, 바꾸기 전에 지금 설정을
백업해 되돌릴 수 있게 한다.

## 사용 방법

| 메뉴 | 하는 일 |
|---|---|
| File > Export Settings… | 내보낼 부분 고르기 → (연결을 골랐으면) #108 연결 내보내기 대화상자 → 저장할 파일 → 결과(부분마다 수, 뺀 비밀 수) |
| File > Import Settings… | 파일 고르기 → 읽기·비교(진행 대화상자) → 미리 보기 → 백업 → 가져오기 → (파일에 연결이 있고 골랐으면) #108 암호·연결 미리 보기 → 결과 |
| File > Undo Settings Import… | 가장 최근에 되돌리지 않은 가져오기를 확인(취소가 기본 단추) 뒤 되돌림 → 결과(되돌린 수, 그대로 둔 것) |

내보내기 대화상자의 부분(처음에는 연결만 꺼짐):

| 부분 | 내용 |
|---|---|
| 옵션 | Chromite 번들의 설정 값(사용자가 정한 값만), SQL 템플릿(`templates.xml`), 연결 유형(`connection-types.xml`), 데이터 형식(`dataformat-profiles.xml`) |
| 드라이버 설정 | 사용자 드라이버와 바꾼 기본 드라이버(`drivers.xml` 형식). 내려받은 jar 위치(`<file>`)는 뺌 |
| 쿼리 라이브러리 | 개인 루트(내 쿼리, `<작업 공간>/QueryLibrary`)의 쿼리 파일. 상대 경로 그대로 |
| 스크립트 | 활성 프로젝트의 스크립트 폴더(`Scripts`)의 스크립트와 각 스크립트에 묶은 연결 ID |
| 연결 | #108 연결 내보내기 대화상자로 고른 연결. 비밀번호를 넣으면 그 파일 형식대로 암호로 암호화(12자 이상, 두 번) |

이미 내보내는 패키지라 `MANIFEST.MF`를 고치지 않았다. 쿼리 라이브러리와 스크립트 폴더는 Swing 번들의 것이라 화면 쪽(`SettingsTransferCommands`)이 맡는다.

## 파일 형식 (버전 1)

확장자 `.chromite-settings`("dbeaver"가 들어가지 않는다). 평범한 zip이다.

| 항목 | 내용 |
|---|---|
| `manifest.json` | `{"format":"chromite-settings","version":1,"created":"<ISO-8601>","sections":["PREFERENCES",…]}` |
| `preferences.json` | `{"<노드>":{"<키>":"<값>",…},…}`. 노드는 인스턴스 범위의 번들 이름(`com.seizia.chromite.ui.swing` 등) |
| `config/<이름>` | 옵션 설정 파일 내용(UTF-8) |
| `drivers.xml` | `<drivers><provider id=…><driver …>…</driver></provider></drivers>`(레지스트리 직렬화기 형식, 정리함) |
| `query-library/<경로>.sql` | 쿼리 파일 바이트 그대로(문자 집합·BOM·줄바꿈 유지) |
| `scripts/<경로>` | 스크립트 파일 바이트 그대로 |
| `script-links.json` | `{"<스크립트 경로>":"<연결 ID>"}` |
| `connections.chromite-connections` | #108 연결 파일 그대로(비밀번호를 넣었으면 AES-256-GCM, 아니면 머리말 `encryption: none`) |

- 읽을 때: 항목 20,000개, 항목 하나 20 MB, 전체 200 MB까지. 크기는 머리글 값이 아니라 실제로 읽은 바이트로 센다(압축 폭탄).
  절대 경로, 드라이브 문자(`:`), `..`이 든 항목 이름은 거부하고, 파일을 쓸 때 대상 폴더 밖이면 다시 막는다(zip-slip, `SettingsTransfer.resolveInside`).
- `format`이 다르거나 매니페스트가 없으면 "설정 파일 아님", `version`이 1보다 크면 "더 새 형식". 모르는 부분 이름은 무시한다.

## 비밀은 평문으로 쓰지 않는다

| 무엇 | 어떻게 |
|---|---|
| 연결 비밀번호 | #108 연결 파일에만, 사용자 암호로 암호화해서 들어간다. 비밀번호를 빼면 사용자 이름만 간다 |
| 설정 값 | 이름이 `password`, `passwd`, `passphrase`, `pwd`, `secret`, `token`, `api key`, `credential`, `private key`처럼 보이고 값이 참·거짓·숫자가 아니면 넣지 않는다(`SettingsTransfer.isSecret`). 내보내기 결과에 뺀 수를 알린다. 프록시·Maven·AI 키는 원래 OS 보안 저장소에 있어 설정 값에 없다 |
| 드라이버 속성·매개 변수 | 같은 규칙으로 `<property>`, `<parameter>`를 뺀다 |
| 가져오기 | 다른 곳에서 만든 파일이 그런 값을 담고 있어도 같은 규칙으로 걸러 쓰지 않는다 |
| 쿼리 파일 | 쿼리 라이브러리 규칙 그대로(파일에 비밀번호를 두지 않음, 비밀처럼 보이는 매개변수 기본값은 저장할 때 경고, [swing-query-library.md](swing-query-library.md) "비밀 정보") |
| 백업 | 바뀌는 연결의 백업은 임의 32바이트 암호로 암호화하고, 그 암호는 OS 보안 저장소(`chromite/settings-backup/<백업 파일 이름>`)에만 둔다 |

## 내보내지 않는 것 (이 PC의 상태)

설정 값 중 이 PC의 상태이거나 이 PC의 폴더인 키는 넣지도, 가져오지도 않는다(`SettingsTransferCommands.isExported`).

| 키 | 주인 | 이유 |
|---|---|---|
| `mainWindow.bounds`, `mainWindow.maximized`, `<도구 창>.size`, `<도구 창>.restorePlace` | `MainFrame`, `ToolWindow`, `ToolWindowDocking` | 창 배치(화면 크기에 따라 다름) |
| `registeredServers.expanded`, `objectExplorer.servers` | `RegisteredServersPanel`, `ObjectExplorerServers` | 펼친 그룹, 보이는 서버(연결 ID) |
| `connectDialog.recentDrivers`, `connectDialog.serverHistory.*`, `sqlEditor.recentFiles` | `ConnectionHistory`, `RecentFiles` | 최근 기록 |
| `resultset.lob.lastFolder`, `dataTransfer.export.folder`, `queryLibrary.roots`, `ui.drivers.home`, `qm.logDirectory`, `fallbackOutputDirectory` | 각 화면, 모델 | 이 PC의 폴더 경로 |
| `queryLibrary.lastValues.*`, `queryLibrary.schedule.active.*`, `queryLibrary.alert.*` | `QueryLibraryState` | 설계상 PC마다 두는 값(마지막 매개변수 값, 이 PC에서 예약 실행할지, 경고 상태) |

- 키를 가진 클래스는 상수를 `private`으로 둔다. 다른 클래스 10개의 접근 범위를 바꾸지 않으려고(최소 변경) 키 글자를 한 곳에 주인 이름과 함께 적었다.
- 연결 하나에만 둔 설정(연결 대화상자의 연결별 설정, `data-sources.json`의 `custom-properties`)은 연결 설정의 일부라 "연결"을 고를 때만 간다(브리프: 연결별 설정은 고를 때만).
- 그 밖에 넣지 않는 것: 작업 공간의 창 배치 파일과 쿼리 기록·쿼리 창 복원 파일(`.metadata/chromite-*`), 공유 쿼리 라이브러리 루트(네트워크 폴더, Git 작업 사본 자체가 공유 경로),
  드라이버 jar(다른 PC는 다시 내려받거나 [driver-offline-bundle.md](driver-offline-bundle.md)로 옮김), Maven 저장소 목록(예전 형식 파일에 인증 정보가 들어 있을 수 있어 이번에는 뺌),
  네트워크 프로필(연결이 쓰는 것은 연결 파일에 들어감), Chromite Agent 설정 파일, 스크립트 폴더 밖의 프로젝트 자원.

## 가져오기

### 미리 보기

파일과 이 컴퓨터가 다른 항목만 한 줄씩 보인다(같은 것은 빼고 센다).

| 부분 | 항목 단위 | "여기에 없음/기본값" | "여기와 다름"(충돌) | 둘 다 두기 |
|---|---|---|---|---|
| 옵션: 설정 값 | 노드·키 | 사용자 값이 없고 파일 값이 기본값과 다름(여기 값 칸에 기본값) | 사용자 값이 파일 값과 다름(여기 값·파일 값 칸) | 없음(값 하나) |
| 옵션: 설정 파일 | 파일 하나 | 파일이 없거나 비었음 | 내용이 다름 | 없음(통째로 바꿈) |
| 드라이버 | 드라이버 하나 | 사용자 드라이버가 없음 / 기본 드라이버가 기본값(파일의 설정이 기본값과 다를 때만) | 여기서도 바꾼 드라이버이고 설정이 다름 | 없음 |
| 쿼리 라이브러리 | 쿼리 파일 | 같은 ID도, 같은 자리의 파일도 없음 | 같은 ID의 쿼리가 어느 루트에든 있거나, 내 쿼리의 같은 자리에 다른 파일 | 새 ID의 사본("… copy") |
| 스크립트 | 스크립트 파일 | 같은 경로에 없음 | 같은 경로에 내용이 다른 파일 | 이름 뒤에 ` (2)` |

- 처음 할 일: 여기에 없거나 기본값이면 가져오기, 충돌은 건너뛰기(지금 설정을 모르게 바꾸지 않음). "모든 충돌에"로 한 번에 바꿀 수 있다. 고를 수 없는 할 일은 그 줄에서 빠진다.
- 바꾸기를 막는 것: 쿼리 창에 열린 스크립트(창이 다른 글을 들고 있다가 저장하면 가져온 것을 덮음), 읽기 전용 루트의 쿼리. 둘 다 둘 다 두기는 고를 수 있다.
- 이 제품에 없는 드라이버 공급자의 드라이버는 "이 제품에 없음"으로 보이고 가져오지 않는다.
- 내려받기만 한 드라이버: 직렬화기는 jar를 내려받은 기본 드라이버도 "바뀜"으로 쓴다. 파일 쪽 `<file>`을 뺀 뒤, 이 PC에서 그 드라이버가 기본값이면
  기본값을 같은 방법으로 직렬화해 비교하고 같으면 보이지 않는다(`serializeDefaultDriver`: 직렬화하는 동안만 바뀜 표시).
- 가져오기 단추를 눌러도 지금 설정이 바뀔 수 있어 취소가 기본 단추이고 처음 포커스를 갖는다.

### 적용

1. 바꿀 항목마다 이전 값을 백업에 적고 백업 파일을 저장한다. 저장하지 못하면 아무것도 바꾸지 않는다.
2. 설정 값: 인스턴스 노드에 바로 쓰고 저장한다. 파일에 없는 키는 그대로 둔다(합치기). 번들 설정 저장소는 값을 읽을 때마다 노드를 보므로 대부분 바로 보이고,
   시작할 때만 읽는 값(테마, 글꼴, 아이콘 등)은 다시 시작한 뒤 적용된다(결과에 알림).
3. 옵션 설정 파일: 설정 파일 관리자로 쓰고 다시 읽는다(SQL 템플릿은 `SqlTemplates.reload`, 연결 유형·데이터 형식은 모델의 설정 변경 이벤트).
4. 드라이버: 같은 직렬화기의 파서(`DriversParser`)로 실행 중인 레지스트리에 드라이버마다 합친다. 바꾸기와 기본값인 드라이버는 먼저 기본값으로
   되돌리고(사용자 드라이버는 라이브러리·매개 변수·속성·클라이언트 홈을 비우고) 읽으므로 파일의 설정이 그대로 된다. 그다음 `drivers.xml`을 저장한다.
   연결이 쥔 드라이버 객체가 그대로이고, 나중에 레지스트리가 저장해도 가져온 값이 남는다(파일만 바꾸면 메모리의 값이 다음 저장 때 덮어쓴다).
5. 쿼리 라이브러리: 쿼리 라이브러리 가져오기와 같은 규칙(`QueryLibraryArchive.write`: 덮어쓰기, 새 ID의 사본, 같은 이름이면 ` (2)`)으로 내 쿼리에 쓴다.
   새로 생긴 파일은 쓰기 전후 목록의 차이로 찾아 백업에 적는다.
6. 스크립트: 정한 경로에 쓴다.
7. 연결(골랐을 때): #108과 같은 암호 묻기(틀리면 다시 묻기)와 연결 미리 보기. 바꾸기를 고른 연결(연결 중이 아닌 것)을 먼저 백업하고 가져온다.
8. 스크립트 연결 묶기: 가져온 스크립트의 묶은 연결 ID가 이 프로젝트에 있으면(연결을 함께 가져왔거나 원래 있으면) 묶는다. 연결 뒤에 하는 이유다.
9. 쿼리 라이브러리·Scripts 창·탐색기를 새로 고치고 결과(부분마다 수, 다시 시작 안내, 되돌리기 안내, 실패한 것)를 알린다. 한 부분이 실패해도 나머지는 가져온다.

### 트랜잭션

설정 가져오기와 되돌리기는 세션을 건드리지 않는다(공통 규칙의 트랜잭션 안전 규칙).

- 연결 중인 연결은 바꾸지 않는다(#108과 같음). 되돌리기도 연결 중인 연결은 지우거나 바꾸지 않고 결과에 적는다.
- 연결 유형(자동 커밋 기본값, 실행 확인 등)을 가져와도 열린 세션의 커밋 방식은 바뀌지 않는다. 연결이 쥔 유형 객체는 다시 시작할 때까지 그대로이고,
  새 유형은 다시 시작한 뒤 연결할 때 적용된다.

## 백업과 되돌리기

- 위치: `<작업 공간>/.metadata/chromite-settings-backups/<yyyyMMdd-HHmmss-SSS>.chromite-settings-backup`(zip). 최근 10개만 두고, 지우는 백업의 연결 암호도 지운다.
- 내용(`backup.json`): 설정 값(노드, 키, 이전 값, 가져온 값), 설정 파일(이전 내용, 쓴 내용의 SHA-256), 드라이버(상태: 없었음·기본값·바뀌어 있었음, 이전 요소),
  파일(경로, 이전 내용 또는 없었음, 쓴 내용의 SHA-256), 자원 속성(스크립트 연결 묶기의 이전 값), 연결(바뀐 연결의 암호화 백업, 가져온 연결 ID, 바꾼 연결 ID).
- 되돌리기(가장 최근의 되돌리지 않은 백업, 가져오기 순서의 반대):

| 항목 | 되돌리는 방법 | 그대로 두는 경우 |
|---|---|---|
| 설정 값 | 이전 값을 다시 쓰거나(없었으면) 지움 | 지금 값이 가져온 값과 다름(가져온 뒤 다시 바꿈) |
| 설정 파일 | 이전 내용을 쓰고 다시 읽음(없었으면 빈 내용 = 사용자 설정 없음) | 지금 내용의 해시가 쓴 내용과 다름 |
| 드라이버 | 없었으면 지움, 기본값이었으면 기본값으로, 바뀌어 있었으면 기본값으로 되돌린 뒤 이전 요소를 읽음. `drivers.xml` 저장 | 가져와 생긴 드라이버를 연결이 쓰고 있음 |
| 파일(쿼리, 스크립트) | 이전 내용을 쓰거나(없었으면) 지움 | 지금 내용의 해시가 쓴 내용과 다름, 파일이 없어짐 |
| 스크립트 연결 묶기 | 이전 자원 속성을 쓰거나 지움 | |
| 연결 | 가져와 생긴 연결을 지우고, 바꾼 연결을 백업으로 다시 바꿈(같은 ID, 비밀번호 포함) | 연결 중 |

- 백업에는 되돌렸다는 표시를 남긴다. 다시 되돌리기를 고르면 그 앞의 가져오기를 되돌린다.
- 확인 대화상자는 바꾸는 일이라 "가져오기 되돌리기 / 취소"이고 취소가 기본 단추다(`SwingPlatformUI.confirmChange`).
- 가져오기 중간에 앱이 죽으면 백업에는 바꾸기 전 값은 있지만 새로 생긴 쿼리 파일이 빠질 수 있다(쓴 뒤에 적으므로). 그때 되돌리기는 그 파일을 남긴다.
