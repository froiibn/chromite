# Query Manager 도구 창

## 목적

- 쿼리 관리자(Query Manager, QM)가 기록한 **모든 실행**을 한 표로 본다. 쿼리 창의 쿼리 기록(Query > Query History)은 쿼리 창이 실행한 문장만
  담지만, 이 창은 결과 필터·정렬, 스크립트, 유틸리티 쿼리(`SET search_path`, `use <db>` 등), 메타데이터 읽기, 커밋·롤백, 연결·끊기까지 보인다.
- SWT의 Query Manager 보기(`QueryManagerView`, `QueryLogViewer`)와 SQL 편집기의 실행 로그(`SQLLogPanel`)에 해당한다(swt-parity A-C6, B-S26).
- 지원 범위: 쿼리 관리자는 모델 공통이라 Chromite가 연결하는 모든 데이터베이스(JDBC로 100개 넘음)에 같다. 확인은 PostgreSQL과 SQL Server에서 했다.

## 사용법

- **보기 > 쿼리 관리자**(View > Query Manager). 메인 창 아래 가장자리에 넓게 열린다(처음에는 숨김). 다른 도구 창처럼 끌어 옮기거나 띄울 수 있다.
- 표의 열: 시각(문장 시작, 마우스를 올리면 날짜까지), 연결, 세션(쿼리 창은 `SQLEditor <SQLQueryN.sql>`, 메타데이터는 `Metadata`), 종류, SQL,
  걸린 시간, 행(읽은 행·바꾼 행), 결과(성공, 오류 코드와 메시지, 실행 중), 트랜잭션(자동 커밋, 열림, 커밋함·롤백함과 시각).
  오른쪽은 고른 행의 전체 문장(연결 방언으로 강조)이고, 오류는 그 아래 주석 줄로 보인다.
  오류 행은 오류 색, 실행 중인 행은 굵게, 유틸리티·메타데이터 쿼리는 흐린 색이다. 새 행이 맨 위다.
- 필터
  - **찾기 칸**: 문장, 연결 이름, 세션 이름, 오류에서 대소문자 무시로 찾는다. 한 쿼리 창의 실행만 보려면 창 이름(`SQLQuery2`)을 넣는다.
  - **연결 목록**: 기록에 나온 연결.
  - **보일 항목**(깔때기 단추): 연결, 트랜잭션, 쿼리, 그리고 쿼리 종류(직접 실행한 쿼리, 결과 필터와 정렬, 스크립트, 유틸리티 쿼리, 메타데이터 읽기,
    DDL 읽기). 메뉴는 고르는 동안 열려 있고 바꾸면 바로 저장된다. 기본은 트랜잭션과 사용자 쿼리 세 종류다.
- 행에서(도구 막대, 오른쪽 클릭 메뉴)
  - **쿼리 창에서 열기**(두 번 누르기도 같음): 고른 문장을 실행한 순서대로 그 연결의 새 쿼리 창에 넣는다. **실행하지 않는다.** 둘 이상이면 끝에 `;`가
    없는 문장에 붙인다. 연결을 지웠으면 연결 없는 창으로 연다.
  - **문장 복사**(Ctrl+C, Edit > Copy도 같음): 같은 순서·같은 형식의 글자를 클립보드에 넣는다.
  - **트랜잭션 보기**: 고른 문장(또는 커밋·롤백 행)이 속한 트랜잭션의 행만 보이고, 위 줄에 "QM-PG(SQLEditor <SQLQuery2.sql>)의 트랜잭션: 열림 / 커밋함 09:53:07"을
    적는다. **모두 보기**로 돌아간다. 자동 커밋으로 실행한 문장은 트랜잭션이 없어 꺼진다. 보는 중에 커밋하면 커밋 행과 상태가 바로 바뀐다.
  - **지우기**: 이 목록만 비운다. 쿼리 관리자의 기록, SQL 로그 파일, 쿼리 기록은 그대로다. 지운 뒤 실행한 것만 다시 쌓인다.

## 설계 결정과 이유

- **내용은 쿼리 관리자가 메모리에 둔 기록**(`QMMCollectorImpl`의 마지막 1만 개 이벤트)이다. 처음 보일 때 기록 전체를 한 번 읽고(`getEventBrowser(true)`),
  그 뒤는 쿼리 관리자의 알림(0.25초마다 모아서 옴)을 EDT에서 더한다. 이벤트는 객체마다 한 행으로 모은다(실행의 시작·가져오기·끝은 같은 행,
  커밋·롤백은 트랜잭션이 끝난 이벤트, 연결은 연결함·끊음마다 한 행). 행은 모델 객체를 들고 있어 실행이 끝나거나 커밋되면 다음 알림 때 바뀐다.
  두 경로로 같은 이벤트가 와도 행 열쇠(객체 id, 연결 행은 동작·시각)로 합친다.
- **알림은 처음 보일 때부터 앱을 닫을 때까지 받는다.** 숨겼다가 다시 보일 때 기록을 다시 읽으면 지운 행이 돌아오기 때문이다. 숨긴 동안은 행만 고치고
  표는 다시 보일 때 거른다. 한 번도 열지 않으면 아무것도 받지 않는다. 메인 창을 닫을 때 알림 등록을 푼다(쿼리 관리자가 "listeners are still open"을
  남기지 않음, 실행 확인).
- **보일 종류는 쿼리 관리자 설정 `qm.objectTypes`·`qm.queryTypes`다**(#151의 Options > Logs "기록할 것"·"쿼리 종류"와 같은 키, SWT도 같았다).
  거르기는 SQL 로그 파일과 같은 `DefaultEventFilter`다. 그래서 이 창에서 메타데이터 읽기를 켜면 SQL 로그 파일도 메타데이터 읽기를 기록한다.
  두 곳이 다른 기준을 갖지 않게 하려는 것이다. 이 때문에 Options > Logs의 두 줄은 로그 파일을 꺼도 켜 두고 "보기 > 쿼리 관리자에 보일 항목도 같음"이라고
  적었다(전에는 로그 파일을 끄면 회색이었다). 기록은 종류와 상관없이 다 하므로 메타데이터 읽기를 나중에 켜도 지난 것까지 보인다.
  `qm.maxEntries`(SWT 표의 최대 행 수, 기본 200)는 쓰지 않는다. 메타데이터를 켜면 200행은 몇 번의 클릭으로 넘치고, 메모리 기록 크기가 이미 위 한계다.
- **트랜잭션 보기는 표 안의 필터**다. 지난 트랜잭션과 닫힌 세션의 트랜잭션도 고를 수 있어야 해서, 한 문맥의 지금 트랜잭션을 보는 트랜잭션 로그 창
  (`TransactionLogDialog`, [transactions.md](transactions.md))을 쓰지 않았다. 트랜잭션은 한 연결의 것이라 연결 필터 대신 쓰이고, 찾기 글자와 보일 종류는 그대로 적용한다.
- **열기는 실행하지 않는다.** 쿼리 창에 글자만 넣는다(SWT의 "Open in SQL console"과 같음). 쿼리 창을 열면 그 창의 세션이 연결되어 연결·커밋 행이 생길 수 있지만
  문장은 실행되지 않는다(실행 확인). 문장은 쿼리 관리자가 적은 그대로라 바인딩한 실행은 값이 들어간 글자다. 열 때 DB·스키마는 바꾸지 않는다(창의 기본값).
- **암호**: 암호가 든 모델 문장은 쿼리 관리자에 기록하지 않으므로([password-handling.md](password-handling.md)) 이 창에도 나오지 않는다. 사용자가 쿼리 창에
  직접 쓴 문장은 쿼리 기록과 같이 보인다.
- 행 수 한계 1만 개, 앱을 다시 시작하면 비어 있다(지난 실행은 SQL 로그 파일).

## SWT 대비

| SWT | Chromite |
|---|---|
| 아래 보기, 검색 칸, 열(시각·종류·텍스트·걸린 시간·행·결과·연결·문맥) | 같음. 열에 트랜잭션을 더함, 세션 = SWT의 문맥 |
| 오른쪽 클릭 메뉴의 쿼리 종류·개체 종류 체크(같은 `qm.*` 키) | 보일 항목 메뉴(같은 키) |
| Open in SQL console, Copy, Copy All Fields, Delete, Select All, Clear Log, Refresh | 쿼리 창에서 열기, 문장 복사, 지우기. 행 하나씩 지우기, 모든 칸 복사, 새로 고침(알림으로 늘 최신)은 없음 |
| 행 두 번 누르기 → 이벤트 상세 대화상자 | 오른쪽 미리 보기, 두 번 누르기는 쿼리 창에서 열기 |
| 열 머리글 정렬 | 없음(새 행이 위) |
| 트랜잭션 상태 색(커밋 안 된 문장 바탕색) | 트랜잭션 열과 트랜잭션 보기 |
| SQL 편집기 안의 실행 로그 패널(그 편집기의 문맥만) | 이 창의 세션 열과 찾기 글자(창 이름) |

## 확인 (2026-11-08)

앱 하나(`CHROMITE_DATA`와 작업 공간은 scratch)를 영어(`-nl en`)와 한국어(`-nl ko`)로 띄우고, 같은 프로세스 안에서 Swing API로만 조작했다(화면 입력 없음).
PostgreSQL 17(수동 커밋 연결)과 SQL Server 2022(자동 커밋 연결)의 scratch 데이터베이스 `chr_query_manager`.

| 확인 | 결과 |
|---|---|
| 창을 열기 전에 실행한 문장 | 처음 열 때 기록에서 읽어 보임 |
| PostgreSQL 스크립트(SELECT, UPDATE, SELECT) | 세 행, 종류 "스크립트", 읽은 행·바꾼 행, 트랜잭션 "열림" |
| UPDATE 행에서 트랜잭션 보기 | 그 트랜잭션의 세 행만, 위 줄 "…의 트랜잭션: 열림" |
| 그 쿼리 창에서 커밋 | 커밋 행이 더해지고 세 행과 위 줄이 "커밋함 09:53:07"로 바뀜(창을 다시 열지 않고) |
| SQL Server `SELECT * FROM dbo.no_such_table` | 결과 `[208] Invalid object name 'dbo.no_such_table'.`, 트랜잭션 "자동 커밋", 미리 보기 아래 오류 주석 |
| 보일 항목 > 메타데이터 읽기 | `qm.queryTypes`에 `META`가 더해지고 지난 메타데이터 읽기(`Metadata` 세션)까지 보임. 끄면 다시 숨음 |
| 보일 항목 > 유틸리티 쿼리, 연결 | `SET search_path…`, `use chr_query_manager`, 연결함 행 |
| 연결 필터 QM-MSSQL, 찾기 `no_such`, `SQLQuery2` | 그 연결, 그 문장, 그 쿼리 창 세션의 행만 |
| 두 행 고르고 쿼리 창에서 열기 | 새 창 `SQLQuery5.sql - QM-PG`에 오래된 문장 먼저 두 문장, 실행 안 함(새 사용자 문장 행 없음) |
| Ctrl+C(표의 전송 처리기) | 같은 글자 |
| 지우기, 새 실행, 창 숨김 중 실행 뒤 다시 보이기 | 빈 표 → 새 실행만, 숨긴 동안의 실행도 보이고 지운 행은 돌아오지 않음 |
| Options > Logs, 로그 파일 꺼짐 | 기록할 것·쿼리 종류 체크 상자가 켜져 있고 안내 문구가 보임 |
| 앱 닫기 | 디버그 로그에 쿼리 관리자 리스너 경고 없음 |

## 남은 일

- 열 머리글 정렬, 행 하나씩 지우기, 모든 칸 복사(SWT Copy All Fields).
- 쿼리 창에서 열 때 기록된 DB·스키마(`QMMStatementExecuteInfo.getCatalog/getSchema`)로 창의 기본값을 맞추기.
