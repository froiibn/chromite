# 쿼리 편집기 열(사각형) 선택

## 목적

기업 환경 사용자 요청(앱 변경 #49, 2026-11-11): "쿼리 편집 부분에서 alt를 누른 상태에서 세로로 선택하는 커서가 안 된다".
SSMS·Visual Studio처럼 Alt+끌기로 사각형을 고르고, 여러 줄의 같은 열에 한 번에 입력·삭제·붙여넣기를 한다.

쿼리 편집기(`SqlEditorPanel.SqlTextArea extends RSyntaxTextArea`)는 사각형 선택도 다중 캐럿도 없다(RSyntaxTextArea 4.0.1에 없음,
origin/devel의 ui.swing에 관련 코드 0건). 그래서 직접 만들었다.

## 동작

| 입력 | Windows·Linux | macOS | 동작 |
|---|---|---|---|
| 사각형 고르기 | Alt+끌기 | Option(⌥)+끌기 | 누른 칸에서 놓은 칸까지. Shift를 함께 누르고 클릭하면 보이는 사각형을 넓힌다 |
| 키로 넓히기 | Shift+Alt+방향키 | ⇧⌥⌘+방향키 | 캐럿에서 시작해 캐럿 쪽 모서리를 옮긴다. 위·아래는 접힌 줄을 건너뛴다 |
| 입력 | 글자 | 글자 | 모든 줄의 사각형 글자를 지우고 그 자리에 넣는다. 폭이 0이면(세로 캐럿) 모든 줄의 같은 열에 넣는다 |
| Backspace / Delete | | | 사각형 글자를 지운다. 폭이 0이면 줄마다 앞 / 뒤 글자 하나. 줄 끝 뒤(빈 칸)에서는 지우지 않고, Delete는 줄을 잇지 않는다 |
| Tab | | | 모든 줄에 탭(공백으로 탭 설정이면 공백). 템플릿 펼치기는 하지 않는다 |
| 복사 / 잘라내기 | Ctrl+C / Ctrl+X | ⌘C / ⌘X | 줄마다 사각형 글자를 잘라 줄바꿈으로 이어 복사한다(빈 칸은 채우지 않음). Edit 메뉴·오른쪽 클릭 메뉴도 같다 |
| 붙여넣기 | Ctrl+V | ⌘V | 붙일 글의 줄 수가 사각형 줄 수와 같으면 줄마다 한 줄씩, 한 줄이면 모든 줄에 같은 글, 그 밖이면 사각형 글자를 지우고 캐럿 쪽 모서리에 한 번 |
| Enter | | | 사각형 글자를 지우고 열 선택을 끝낸 뒤 캐럿 쪽 모서리에서 줄을 바꾼다 |
| 되돌리기 | Ctrl+Z | ⌘Z | 열 편집 하나(글자 하나, 붙여넣기 하나, 지우기 하나)가 되돌리기 한 번 |
| 대문자 / 소문자 | Ctrl+Shift+U / L | ⇧⌘U / ⇧⌘L | 사각형 안의 글자만 바꾸고 사각형은 남는다 |
| 줄 명령 | 주석(Ctrl+K Ctrl+C·U, Ctrl+/), 블록 주석, 들여쓰기 빼기(Shift+Tab), 서식, 다듬기, 줄 옮기기(Alt+↑↓), 줄 지우기 | | 사각형이 걸친 줄을 보통 선택으로 바꾼 뒤 실행한다 |
| 실행 | F5, Ctrl+Enter(현재 문장), 행 수 세기, 식 계산, Ctrl+L(예상 계획) | F5, ⌘Enter, ⌘L | 보통 선택처럼 사각형의 글을 실행한다(아래 "실행"). 커서부터 실행(Alt+P)은 예전처럼 캐럿부터. 사각형 안이 모두 줄 끝 뒤의 빈 칸이면 "실행할 내용이 없음" |
| 끝내기 | Esc, 방향키, Home/End, PageUp/Down, 보통 클릭, 그 밖에 캐럿을 옮기거나 문서를 바꾸는 모든 것(되돌리기, 찾기, 자동완성 넣기, 모두 선택) | | 캐럿은 캐럿 쪽 모서리에 남는다 |

## 설계 결정

- **Swing 선택은 비워 둔다.** 사각형은 `SqlColumnSelection`이 줄·열 번호로 기억하고, 편집기의 캐럿은 캐럿 쪽 모서리(가장 가까운 글자 경계,
  빈 칸이면 줄 끝)에 둔다. 그래서 선택을 읽는 기존 코드(찾기, 자동완성, 마우스 올림 설명, Ctrl+클릭)는
  사각형을 모르고 캐럿 하나로 예전처럼 동작한다. 실행과 계획만은 사각형을 읽는다(아래 "실행", 2026-11-12). 열 선택이 꺼져 있으면 이 클래스는 Alt+왼쪽 누르기와 (Windows) 마우스에 쓴 Alt의 떼기 말고는 아무 입력도 가로채지 않으므로
  보통 선택은 예전과 같다. 바뀐 것은 Alt+끌기 하나다(전에는 보통 끌기 선택이었다).
- **열은 글자 칸이다.** 탭은 다음 탭 위치까지(탭 크기 4), 한글·한자·전각 글자·이모지는 2칸, 결합 문자·서식 문자와 한글 중성·종성 자모는 0칸.
  칸 경계가 전각 글자나 탭 가운데에 떨어지면 왼쪽 끝은 그 글자 앞, 오른쪽 끝은 그 글자 뒤로 넓힌다(걸친 글자는 선택). 폭이 0인 캐럿은 가까운 경계.
  줄 끝보다 오른쪽은 빈 칸(가상 공간)이고, 그 자리에 입력하면 그 줄을 공백으로 채운 뒤 넣는다(SSMS와 같음).
- **화면 위치는 편집기 보기에서 읽는다.** 실제 글자의 x는 `modelToView2D`, 마우스가 가리킨 글자는 `viewToModel2D`이고, 공백 폭은 빈 칸에만 쓴다.
  대체 글꼴의 한글 폭이 정확히 2칸이 아니어도 사각형이 글자를 따라 그려지고 마우스가 가리킨 글자가 선택된다.
- **접힌 줄은 사각형에 들지 않는다.** 보이지 않는 줄을 몰래 고치지 않기 위해서다. 줄 명령은 보통 선택과 같이 접힌 줄도 포함한다.
- **자동 줄 바꿈이 켜져 있으면 열 선택을 쓰지 않는다.** 한 줄이 여러 화면 줄로 나뉘어 열이 정해지지 않는다. Alt+끌기는 보통 끌기 선택이 되고,
  Shift+Alt+방향키는 오류음이다. 열 선택 중에 줄 바꿈을 켜면 끝난다.
- **고치기는 문서를 아래 줄부터 직접 바꾼다**(위 줄의 위치가 그대로 맞다). 전체를 `beginAtomicEdit`/`endAtomicEdit`로 묶어 Ctrl+Z 한 번에 되돌린다.
- **입력 경로.** 글자는 키 리스너의 `keyTyped`가 받는다(키 바인딩보다 먼저). 따옴표·괄호 짝 넣기(`InsertQuoteAction`)는 넣은 뒤 캐럿을 옮겨
  열 선택을 끝내므로 거치지 않는다. IME(한글 조합)의 확정 글자와 붙여넣기는 `replaceSelection`으로 들어오므로 편집 영역이 그것을 먼저 넘긴다.
  조합 중인 글자는 Swing이 캐럿(캐럿 줄)에만 넣고, 그동안의 캐럿·문서 변경은 열 선택을 끝내지 않는다(`processInputMethodEvent`를 감쌈).
  확정되면 모든 줄에 들어간다.
- **복사·잘라내기.** `copy()`/`cut()`을 재정의해 Edit 메뉴, 오른쪽 클릭 메뉴가 같은 동작을 쓴다. 편집기의 Ctrl+C·Ctrl+X는 RSyntaxTextArea의
  서식 복사(`RSTA.CopyAsStyledTextAction`, Swing 선택을 직접 읽음)라 `copy()`를 부르지 않으므로, 키 리스너가 그 키(와 Ctrl+Insert·Shift+Delete)를
  먼저 받아 `copy`로 보낸다(`COPY_ACTIONS`, `CUT_ACTIONS`). RSyntaxTextArea는 Swing 선택이 비면 오른쪽 클릭 메뉴의
  Copy·Cut을 끄므로 `configurePopupMenu`에서 다시 켠다. 복사는 시스템 클립보드에 보통 글로 넣는다(사각형 표시 형식은 두지 않음).
- **Alt 떼기.** Windows에서 Alt를 눌렀다 떼면 FlatLaf `MnemonicHandler`가 메뉴 막대를 고른다. 그 사이에 다른 키가 오면 취소하지만 마우스 이벤트는
  취소하지 않는다. Alt를 누른 채 마우스를 쓴 뒤의 Alt 떼기는 이 클래스가 아니라 모든 창에 한 규칙인 `AltMouseMenuGuard`가 소비한다.
  아래 "Alt 떼기와 메뉴 막대(앱 변경 #100, #102)"를 본다.
- **그리기.** 편집기 강조 표시기(`Highlighter`)에 범위와 상관없는 강조 하나를 넣어 글자 밑에 사각형을 칠하고(선택 색), 포커스가 있으면 줄마다
  캐럿(캐럿 색, 1픽셀)을 그린다. 깜빡이는 편집기 자신의 캐럿은 숨긴다(빈 칸에서는 줄 끝에 있어 어긋난다).
- **줄 명령.** 사각형을 걸친 줄의 보통 선택으로 바꿔 실행한다: `runCommand`의 편집 명령(대문자·소문자는 사각형 안, 템플릿 넣기는 캐럿에서),
  그리고 키 바인딩 중 줄 단위 RSyntaxTextArea 동작(`LINE_ACTIONS`: 주석 토글, 들여쓰기 빼기, 줄 위·아래로 옮기기, 줄 지우기).
- **macOS 키.** Shift+Option+방향키는 macOS의 단어 선택이므로 VS Code처럼 ⇧⌥⌘+방향키를 쓴다. 마우스는 Option+끌기.

## 실행 (2026-11-12)

- **전:** 사각형이 있어도 Swing 선택이 비어 있어 F5는 편집기 글 전체를, 현재 문장 실행(Ctrl+Enter)·행 수·식 계산은 캐럿의 문장을, 예상 계획은 글 전체를
  실행했다(위 "Swing 선택은 비워 둔다"의 결과). SSMS는 사각형 글자를 실행한다.
- **지금:** 실행(`SqlEditorPanel.execute`, 커서부터 실행 제외)과 예상 계획(`explainEstimatedPlan`)은 사각형을 보통 선택처럼 쓴다.
  `SqlColumnSelection.getRunText`가 실행할 글을 만든다: 편집기 글에서 사각형의 첫 글자부터 마지막 글자까지의 범위, 그 안에서 사각형 밖 글자(사각형 왼쪽·오른쪽,
  사이의 접힌 줄)는 공백으로 바꾸고 줄바꿈은 둔다. 그래서 실행하는 내용은 사각형의 줄을 줄바꿈으로 이은 것과 같고(줄 앞뒤 공백만 더 있음),
  - 문장 위치가 편집기 글의 위치와 그대로 같다. 실행 중 문장 강조(#44), 오류 줄 표시, Messages의 오류 위치 연결, Oracle 컴파일 오류 줄이 고치지 않아도 맞는다.
    사각형 글을 따로 이어 붙인 글로 실행하면 이 위치들을 모두 바꿔 계산해야 한다.
  - 줄을 넘는 문자열 상수가 사각형에 걸리면 그 안에 사각형 밖 자리만큼 공백이 들어간다(그대로 이어 붙인 글과의 유일한 차이).
- 실행 기록·Query Manager에 남는 문장 글에도 둘째 줄부터 사각형 왼쪽 열만큼의 공백이 앞에 붙는다.
- 커서부터 실행은 "캐럿 문장부터 끝까지"라 사각형과 맞지 않아 예전처럼 캐럿에서 시작한다.
- **확인(2026-11-12, 150%, 테스트 에이전트, SQLite):** 글 `-- SELECT 11 AS a; -- x` / `-- SELECT 22 AS b; -- y` / `-- SELECT * FROM nosuch_r2; z`에서
  1-2줄 3-18열 사각형 + F5 → 쿼리 기록에 `SELECT 11 AS a`, `SELECT 22 AS b` 두 문장(주석 앞뒤는 빠짐). 2줄만의 사각형 + 현재 문장 실행 → `SELECT 22 AS b`.
  3줄의 `SELECT * FROM nosuch_r2;` 사각형 + F5 → 실패 표시가 편집기 3번째 줄, Messages "메시지 1, 줄 3". 편집기 글은 바뀌지 않음.
  캡처 `D:\Tools\_scratch\chromite-small-fixes-r2\shots\col-run-*.png`. 예상 계획(Ctrl+L)은 코드만 같은 방식으로 고쳤고 실행해 보지 않았다.

## 창 단축키 (2026-11-15)

- **결함:** 열 선택이 켜져 있으면 F5, Alt+P, Alt+Pause, Ctrl+L, Ctrl+S 등 편집기 키 바인딩이 없는 키가 아무 일도 하지 않았다.
  `SqlColumnSelection.handleKeyPressed`가 키 바인딩 이름을 `COPY_ACTIONS.contains(action)`로 보는데, 바인딩이 없으면 `action`이 null이고
  `Set.of(...)`의 `contains(null)`은 `NullPointerException`을 던진다. 예외가 키 처리를 끊어 메뉴 단축키까지 가지 못했다. 위 "실행"의 확인(2026-11-12)은
  시험 에이전트가 실행 메서드를 바로 불러 키 경로를 지나지 않아 이를 보지 못했다. Ctrl+Enter(현재 문장 실행)는 예외는 없었지만 Enter 처리가
  열 선택을 끝낸 뒤에 실행되어 사각형이 아니라 캐럿의 문장을 실행했다.
- **고침:** 편집기 바인딩이 없는 키는 아무것도 하지 않고 넘긴다(창 단축키가 그대로 받음). 명령 키(Ctrl, macOS ⌘)와 누른 Enter도 넘긴다.
  같은 클래스에서 null이 불변 컬렉션에 들어가는 곳은 이 한 곳뿐이다(`LINE_ACTIONS`는 문자열일 때만 봄).
- **열 선택 중 창 단축키의 결과(위 "실행"의 규칙 그대로):** 사각형은 남는다(단축키가 캐럿을 옮기거나 글을 바꿀 때만 끝남).

  | 키 | 결과 |
  |---|---|
  | F5(와 Execute의 다른 키) | 사각형의 글을 실행 |
  | Ctrl+Enter | 사각형을 보통 선택처럼: 선택한 글을 한 문장으로 실행 |
  | Alt+P | 예전처럼 캐럿(캐럿 쪽 모서리)의 문장부터 끝까지 |
  | Ctrl+L | 사각형의 글로 예상 계획 |
  | Ctrl+S | 저장(새 파일이면 저장 대화상자), 사각형은 남음 |
  | Ctrl+W | Chromite가 묶지 않은 키라 아무 일도 없음 |
  | Esc, 방향키, Enter(수정자 없음), Ctrl+Z | 예전처럼 열 선택을 끝냄 |

- **확인(빌드한 앱, Windows, 시험 PostgreSQL, 앱 창 안 Robot 키 입력, 쿼리 관리자 기록):** 3줄 글에서 0–1줄 0–24열 사각형.
  F5 → `SELECT 'chr_ax_c1' AS a`, `SELECT 'chr_ax_c2' AS b`; Ctrl+Enter → 두 줄을 한 문장으로; 1줄만의 사각형 + Ctrl+Enter → `SELECT 'chr_ax_c2' AS b`;
  Alt+P → 캐럿 줄부터 c2, c3; Ctrl+L → c1, c2의 EXPLAIN; Ctrl+S → 저장 대화상자, Esc 뒤 사각형 그대로; Ctrl+W → 변화 없음. 모든 단계 뒤 사각형이 남음.
  편집: 폭 0 세로 캐럿(3줄)에서 Ctrl+C·Ctrl+X는 열 선택이 받음(폭 0이라 클립보드를 건드리지 않음), `z` 입력이 세 줄에, Backspace가 세 줄에서 지움,
  붙여넣기 경로(`replaceSelection("q")`)가 세 줄에, Ctrl+Z가 되돌리고 열 선택을 끝냄. 디버그 로그에 예외 0건(고치기 전 빌드는 키마다
  `NullPointerException ... SqlColumnSelection.handleKeyPressed`). 폭이 있는 사각형의 복사·잘라내기는 시스템 클립보드를 쓰므로 실행하지 않았고,
  그 코드는 바뀌지 않았다.

## Alt 떼기와 메뉴 막대 (앱 변경 #100, 2026-11-12)

- **증상(사내 환경, 26.0.5):** "편집기에서 alt를 누르면 처음에 세로로 선택되다가 메뉴로 커서가 이동되어버린다". Alt+끌기로 사각형을 고른 뒤
  Alt를 떼면 메뉴 막대의 첫 메뉴(파일)가 골라지고 포커스가 루트 창으로 가서, 다음 입력이 편집기에 들어가지 않았다.
- **원인:** `SqlColumnSelection`은 Alt+끌기 뒤의 Alt 떼기를 소비해 FlatLaf `MnemonicHandler.processKeyEventOnWindows`(flatlaf 3.8,
  `com/formdev/flatlaf/MnemonicHandler.java` 114–169행: 첫 Alt 누르기에서 "떼면 메뉴 고르기"를 켜고, Alt가 아닌 키는 이를 끄고, 소비되지 않은
  Alt 떼기에서 첫 메뉴를 고름)를 막으려 했다. 그런데 그 표시(`altUsed`)를 **모든** Alt 누르기에서 지웠다. Alt를 누르고 있으면 Windows 키 반복이
  Alt 누르기를 계속 보내므로(원격 세션에서는 더 잦다), 끌기 중이나 끌기 뒤에 온 반복 누르기가 표시를 지우고 떼기는 메뉴를 골랐다.
  처음 확인(앞 "확인")은 합성 이벤트라 키 반복이 없어 지나쳤다. 또 표시는 열 선택이 시작될 때만 붙어서, 자동 줄 바꿈이 켜진 편집기의
  Alt+끌기(보통 끌기 선택)와 마우스를 먼저 누르고 Alt를 누른 끌기도 메뉴를 골랐다.
- **고침:** 표시는 Alt 떼기(소비)와 포커스 잃기에서만 지운다. 표시는 `processMouseEvent` 첫 줄 한 곳에서, Alt를 누른 채 온 모든 마우스
  누르기·끌기(열 선택 여부와 상관없음)에 붙인다. Windows에서만 붙인다(`MnemonicHandler`가 메뉴를 고르는 것은 Windows뿐, macOS의 Option과 Linux의
  Alt는 메뉴 키가 아니다).
- **방식을 고른 이유:** FlatLaf가 이미 "소비된 Alt 떼기는 메뉴를 고르지 않는다"는 길을 열어 두었고, 편집기는 Alt 떼기를 받는 포커스 주인이다.
  전역 키 후처리기나 `MnemonicHandler`의 정적 상태를 고치는 방법은 LaF 내부에 기대고 다른 창·구성 요소의 Alt에도 끼어든다.
  Alt를 마우스 수정자로 쓰는 곳은 쿼리 편집기 하나다(`isAltDown`·`ALT_DOWN_MASK`를 마우스 이벤트에 쓰는 코드는 `SqlColumnSelection`뿐).
  (#102에서 바뀜: 휠과 다른 창도 다루려고 이 표시를 지우고 모든 창의 키 디스패처 하나로 옮겼다. 아래 "모든 창으로 넓힘".)
- **그대로인 것:** Alt만 눌렀다 떼기(키 반복 포함)는 메뉴 막대를 고르고, Alt+F는 파일 메뉴를 열고, Esc는 메뉴를 닫아 편집기로 돌아오고, F10,
  Alt+키 단축키(Alt+PageDown 등)는 예전과 같다. Alt+끌기를 한 다음 Alt만 다시 눌렀다 떼면 메뉴가 골라진다(표시가 남지 않음).
- **같은 원인의 다른 곳:** 결과 표에서 Alt+클릭, 어디서든 Alt+휠 뒤에 Alt를 떼면 메뉴 막대가 골라진다. 이 동작들에는 Alt의 뜻이 없고
  (Alt+클릭은 보통 클릭, Alt+휠은 보통 스크롤) Windows의 Alt 규칙대로이므로 고치지 않았다.
- **확인(빌드한 앱, Windows 11, 실제 OS 입력: 앱 프로세스 안에서 `java.awt.Robot`, 매 입력 전 Chromite 창이 포커스 창인지 확인, 영어·한국어,
  연결 없는 쿼리 창과 SQLite에 연결해 쿼리를 실행한 쿼리 창).** 키 반복은 Alt를 누른 채 Alt 누르기를 더 보내 흉내 냈다.

  | 순서 | 전: 포커스 / 메뉴 / 사각형 | 후 |
  |---|---|---|

### 모든 창으로 넓힘 (앱 변경 #102, 2026-11-12)

- **요청:** "알트키 관련 사항은 고쳐라. 줄이 길면 스크롤도 할 수 있다". 긴 줄에서 Alt를 누른 채 열 선택을 하며 휠로 스크롤하고, 결과 표 등
  다른 곳에서도 Alt를 누른 채 마우스를 쓴다. 위 #100의 표시는 편집기의 마우스 누르기·끌기에만 붙어서, Alt+휠(편집기 포함 어디서나)과
  다른 구성 요소의 Alt+클릭·끌기 뒤에 Alt를 떼면 메뉴 막대가 골라졌다(아래 표의 "전").
- **규칙(Windows만):** Alt를 누른 채 Chromite의 어느 창에서든 마우스를 쓰면(누르기·클릭·끌기·휠, 편집기·여백·스크롤 막대·결과 표·개체 탐색기·
  도구 창 머리글·도구 막대·대화상자 모두) 그 Alt를 떼도 메뉴 막대가 골라지지 않고 포커스는 그대로다. Alt만 눌렀다 떼기, F10, Alt+글자,
  Alt+키 단축키는 그대로다.
- **구조:** `AltMouseMenuGuard`(새, ui.swing) 한 곳. `AWTEventListener`(마우스·끌기·휠·창 포커스)가 Alt가 눌린 마우스 누르기·끌기·휠을 표시하고,
  `KeyEventDispatcher`가 표시된 Alt 떼기를 소비한다. `MainFrame` 생성자에서 설치(Windows에서만)하고 주 창이 닫히면(`windowClosed`) 지운다.
  `SqlColumnSelection`의 표시(`altUsed`), Alt 떼기 키 리스너, 포커스 잃기의 지우기는 지웠다(같은 일을 두 곳에서 하지 않음).
- **방식을 고른 이유(JDK 25 `DefaultKeyboardFocusManager`):** 키 이벤트는 `preDispatchKeyEvent`에서 키 디스패처 → `dispatchKeyEvent`에서
  포커스 주인(소비되지 않았을 때) → 키 후처리기(FlatLaf `MnemonicHandler`는 LaF 설치 때 등록) → 창 peer 순서로 간다. 후처리기 순서는 등록 순서라
  테마를 바꿔 LaF를 다시 설치하면 바뀐다. 키 디스패처는 항상 그 앞이다. 디스패처는 표시된 Alt 떼기를 먼저 포커스 주인에게 그대로 보내고
  (`redispatchEvent`: 키 리스너·떼기 키 바인딩·AWT 리스너는 예전처럼 받음) 소비한 뒤 `false`를 돌려준다. 그러면 관리자는 다시 보내지 않고,
  후처리기는 소비된 떼기를 받아 메뉴를 고르지 않으며(밑줄 숨기기와 누르기 횟수 초기화는 그대로 함), peer도 소비된 이벤트는 창의 기본 처리로
  넘기지 않는다. 포커스가 대화상자나 팝업에 있어도 같은 길이다. Alt 떼기를 듣는 코드는 앱에 없었다(`keyReleased`·떼기 키 바인딩은
  `SqlColumnSelection`의 것뿐, `OptionsDialog`의 AWT 리스너는 아무 키 떼기에나 저장 상태를 다시 셈).
- **표시 지우기:** Alt 떼기마다, 그리고 포커스가 이 프로그램을 떠날 때(`WINDOW_LOST_FOCUS`, 상대 창 없음: Alt+Tab이면 떼기는 다른 프로그램이
  받는다). Alt 누르기에서는 지우지 않는다(키 반복). 오른쪽 Alt가 AltGr(`VK_ALT_GRAPH`)로 오면 그 떼기는 소비하지 않고 표시만 지운다.
- **휠과 사각형:** 끌기 중이나 두 끌기 사이의 휠은 화면만 스크롤하고(세로 54px, Shift+휠은 가로) 사각형은 그대로다. 다음 마우스 이동에서 캐럿 쪽
  모서리가 그 자리의 칸으로 넓어진다. 이것은 전과 같다.
- **확인(빌드한 앱, 실제 OS 입력, 영어·한국어, SQLite 연결 뒤 쿼리를 실행한 쿼리 창, 80줄 × 270자 글):** 위 #100 표의 모든 줄이 그대로이고
  (Alt+휠 한 줄만 "파일 골라짐"에서 "안 골라짐"으로), 아래가 바뀌었다.

  | 순서 | 전: 포커스 / 메뉴 | 후 |
  |---|---|---|
  | 긴 줄 Alt+끌기 중 휠, 중 Shift+휠, 두 끌기 사이 휠(키 반복) | 편집기 / 안 골라짐(#100) | 같음, 사각형 넓힘도 같음 |
  | Alt+휠: 편집기(키 반복 포함), 결과 표, 트리 | 루트 창 / 파일 | 휠을 쓴 곳의 포커스 그대로 / 안 골라짐 |
  | Alt+클릭·Alt+끌기: 결과 표 | 루트 창 / 파일 | 결과 표 / 안 골라짐 |
  | Alt+클릭·작은 Alt+끌기: 트리(전은 Query Library 트리, 후는 개체 탐색기 트리) | 루트 창 / 파일 | 그 트리 / 안 골라짐 |
  | Alt+클릭: 도구 창 머리글, 도구 막대 빈 곳, 편집기 여백, 세로 스크롤 막대 | 루트 창 / 파일 | 편집기 / 안 골라짐 |
  | Alt+클릭: 메뉴 막대의 파일 | 파일 메뉴 열림 | 같음 |
  | Alt 누른 채 휠, 그다음 F | 파일 메뉴 열림 | 같음 |
  | Alt+휠, Alt 뗌, Alt만 다시 | 첫 떼기에 파일, 둘째 누르기가 닫음 | 첫 떼기 안 골라짐, 둘째에 파일 골라짐 |

  | Alt+휠 뒤 다른 프로세스의 창(시험용 도우미 창)을 눌러 그곳에서 Alt 뗌, 돌아와 Alt만 | 파일 골라짐 | 같음(표시가 남지 않음) |

  로그 `D:\Tools\_scratch\alt-column-select\logs\`(before2-*, after2-*).
- **확인하지 못한 것:** 실제 Alt+Tab(다른 사용자 프로그램으로 입력을 보내지 않으려고 도우미 창을 눌러 흉내 냄), 실제 원격 세션의 키 반복,
  AltGr 배열 키보드, 도구 창 머리글을 길게 끌기(창이 떨어져 나가므로 클릭만), ERD·계획 그림(같은 리스너가 모든 구성 요소에 걸리므로 따로 하지 않음),
  macOS(설치하지 않는 것을 코드로만 확인).

## 한계

- 사각형으로 복사한 글을 열 선택 없이 붙이면 보통 글로 붙는다(VS의 "사각형으로 붙이기" 형식 없음).
- 조합 중인 한글은 캐럿 줄에만 보이고 확정되면 다른 줄에 들어간다.
- 폭이 다른 글을 줄마다 붙이면 열 선택은 캐럿 줄 끝의 열에 남는다(줄마다 다른 열의 캐럿은 없다).
- Linux 창 관리자 다수가 Alt+끌기를 창 옮기기로 쓴다. 그 환경에서는 Shift+Alt+방향키를 쓴다.

- Alt+끌기로 5줄 사각형(탭 줄, 한글 줄, 짧은 줄 포함), 복사 결과 `a,` / `cc` / (빈 줄) / `한` / `, `. Swing 선택은 빈 채로.
- 입력: 모든 줄의 사각형 글자를 바꾸고 짧은 줄은 공백으로 채움. 두 번째 글자는 세로 캐럿 위치에. Ctrl+Z 한 번에 글자 하나, 되돌리면 열 선택 끝.
- 세로 캐럿(폭 0, 3줄): `-- ` 입력, Backspace 두 번, Delete 한 번이 모든 줄에.
- Shift+Alt+↓↓→→ 뒤 Delete로 사각형 지우기. 빈 칸에서 지운 뒤에도 캐럿이 줄 끝으로 당겨지지 않음.
- Ctrl+C(편집기 키 `RSTA.CopyAsStyledTextAction`): 탭 가운데에서 시작한 왼쪽 끝은 탭 앞, 한글 가운데에서 끝난 오른쪽 끝은 한글 뒤(`LECT 한` / `\tTAB,`).
- 붙여넣기: 3줄 글 → 줄마다(되돌리기 한 번), 2줄 글을 3줄에 → 캐럿 쪽 모서리에 한 번, 한 줄 글 → 모든 줄. 잘라내기.
- 접힌 BEGIN…END(1–3줄 숨김)를 걸친 0–4줄 사각형에 입력하면 0줄과 4줄만 바뀜.
- IME: 조합 중("ㄱ", "가")에는 열 선택 유지, 확정되면 세 줄 모두 "가".
- FlatLaf 메뉴 막대: Alt만 눌렀다 떼면 메뉴가 골라짐(경로 길이 2), Alt+끌기 뒤 떼면 골라지지 않음(0).
- 보통 끌기 선택은 예전 그대로, Alt+클릭(끌기 없음)은 그 자리에 보통 캐럿, 보통 클릭·방향키·Esc·Ctrl+클릭은 열 선택을 끝냄, Ctrl+마우스 이동은 편집기로 감.
- 대문자: 사각형 안만 바뀌고 사각형 유지. Ctrl+K Ctrl+C 주석과 Ctrl+/는 사각형의 두 줄 모두에. Tab은 줄마다 탭.
- 자동완성: 열 편집 뒤 예약 없음, 보통 `.` 입력은 예약됨.
- 자동 줄 바꿈 켬: Alt+끌기가 보통 선택. 읽기 전용 편집기: 입력 거부, 복사는 됨.
- 빈 칸 50열의 캐럿 x가 같은 열 실제 글자의 x와 같음(150%: 374.67 / 374.67, 100%: 408 / 408).
- 화면: 사각형이 글자 밑에 선택 색으로, 빈 칸까지 칠해짐(shots `rect`, `virtual`, 150%·100%).

확인하지 못한 것: 실제 키보드·마우스·한글 IME(합성 이벤트로만), 포커스가 있을 때의 줄마다 캐럿 깜빡이지 않음(처음 실행 화면에서만 봄), macOS.
